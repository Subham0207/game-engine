# FlowScript Notes

This file documents the current FlowScript pipeline and the state-machine transition-condition integration.

## Current architecture

FlowScript is split into clear stages:
- graph authoring (`NodeGraph` + `NodeGraphNodesView`)
- compile to IR (`Flowscript::Compile::Compiler`)
- emit Lua (`LuaEmitter`)
- optional execute (`FlowScript` Execute button)
- decompile back to graph (`FlowScript::deCompile`)

Primary files:
- `Glitter/Sources/FlowScript.cpp`
- `Glitter/Sources/Compiler.cpp`
- `Glitter/Sources/LuaEmitter.cpp`
- `Glitter/Sources/FlowScript/Decompile/LuaSubsetLineParser.cpp`
- `Glitter/Sources/FlowScript/Decompile/DecompileGraphBuilder.cpp`

## Compile pipeline (`FlowScript::compile`)

`FlowScript::compile()` is orchestration-only:
1. Build graph index + validate links/nodes.
2. Compile to IR statements (`Stmt` hierarchy).
3. Emit Lua text from IR.
4. Store compiler diagnostics and append them to FlowScript log.

Output format:
- always prefixed with:

```lua
-- Generated by FlowScript::compile()
```

### Important compile behaviors

- IR covers local assignments, local tables, print, return, and function statements.
- Function statements now carry parameter names in IR (`FunctionStmt::parameters`).
- `LuaEmitter` emits parameterized signatures:

```lua
local node_X = function(t)
    ...
end
```

- `GenericType(name)` nodes have two roles:
  - literal object authoring (field outputs are `FIELD`): emits table + assignments
  - destructuring/object access (field outputs are `PIN`): treated as read-access only

## Decompile pipeline (`FlowScript::deCompile`)

`FlowScript::deCompile(lua)`:
1. parse each supported line into `ParsedStatement`
2. apply statements via `DecompileGraphBuilder`
3. finalize (scope checks, exec-chain linking, pending generic flush)

Supported patterns include:
- `local node_x = <literal>`
- `local node_x = (<a> op <b>)`
- `local node_x = function(...)`
- `print("[LUA]", expr)`
- `return expr`
- generic blocks (`local obj = {}` + `obj.field = value`)

Also supported now:
- function parameter lists in decompile (`function(t)`)
- dotted value resolution for context-like expressions (`t.someField`)

## State-machine transition-condition workflow

State-machine conditions use `StatemachineFlowScript` (derived from `FlowScript`).

Relevant files:
- `Glitter/Headers/NodeGraph/FlowScript/StatemachineFlowScript.hpp`
- `Glitter/Sources/StatemachineFlowScript.cpp`

### Condition source shape

Saved condition chunks are runtime-callable factories:

```lua
return function(t)
    ...
end
```

Default new-link condition:

```lua
return function(t)
    return false
end
```

### Open/edit/save behavior

- Opening a selected transition:
  - unwrap stored condition chunk into editor source
  - decompile into FlowScript graph
  - ensure context node exists and is connected
- Compiling from editor:
  - compile graph as normal FlowScript Lua
  - wrap into runtime condition-chunk format
  - assign to `StateMachineLink::condition`

### Context object in condition graphs

Condition graphs expose context via:
- Function node parameter pin `t`
- `GenericType(t)` destructuring node for properties (`t.field`)

`GenericType(t)` is auto-created for condition editing when context metadata is available.

## Runtime evaluation path

Runtime files:
- `Glitter/Headers/Controls/statemachine.hpp`
- `Glitter/Sources/statemachine.cpp`
- `Glitter/Headers/LuaEngine/LuaCondition.hpp`

Behavior:
- `StateMachine::loadContext<T>(...)` stores context pointer and callbacks.
- Lua evaluation callback now builds a Lua table from reflected `T` fields and passes that table as `t`.
- `LuaCondition` lazily compiles and supports fallback wrapping for non-factory chunks.
- `StateMachine::evaluateLuaCondition(...)` catches exceptions and returns `false` on failure.

## Notes

- FlowScript "Copy Lua" shows raw compile output, not the state-machine wrapper unless saved through transition compile path.
- Transition condition text shown on links is currently raw condition source string.
- Build config includes nested FlowScript source directories; decompile modules under `Glitter/Sources/FlowScript/Decompile/` are compiled automatically.
