# FlowScript Notes

This file documents the current FlowScript pipeline and state-machine transition-condition integration.

## Current architecture

FlowScript is one-way and file-backed:
- graph authoring (`NodeGraph` + `NodeGraphNodesView`)
- graph serialization (`VisualScriptJsonSerializer` to `.flowscript`)
- compile to typed AST (`Flowscript::Compile::Ast`)
- transpile AST to Lua (`LuaTranspiler`)
- optional execute (`FlowScript` Execute button)

Primary files:
- `Glitter/Sources/FlowScript.cpp`
- `Glitter/Sources/Ast.cpp`
- `Glitter/Sources/LuaTranspiler.cpp`
- `Glitter/Headers/NodeGraph/FlowScript/VisualScriptJsonSerializer.hpp`
- `Glitter/Sources/StatemachineFlowScript.cpp`

## Compile pipeline (`FlowScript::compile`)

`FlowScript::compile()` is orchestration-only:
1. Build typed AST from visual nodes/links.
2. Transpile AST to Lua.
3. Store compile diagnostics when compile/transpile throws.
4. Prefix output with generation banner.

Output format:

```lua
-- Generated by FlowScript::compile()
```

## State-machine transition-condition workflow

State-machine transitions persist two file paths in `StateMachineLink`:
- `flowScriptPath` (editor source asset)
- `luaScriptPath` (runtime artifact)

Relevant files:
- `Glitter/Headers/NodeGraph/FlowScript/StatemachineFlowScript.hpp`
- `Glitter/Sources/StatemachineFlowScript.cpp`
- `Glitter/Headers/NodeGraph/Components/StateMachineLink.hpp`

### Source/artifact lifecycle

- Opening a selected transition:
  - load graph from `flowScriptPath` via `VisualScriptJsonSerializer::DeserializeFromFile`
  - if missing, create a default starter graph (`Function(t) -> Return(false)`)
  - ensure context node exists and is connected
- Compiling from editor:
  - compile current graph with `FlowScript::compile()`
  - wrap compiled Lua as runtime callable chunk
  - write wrapped Lua to `luaScriptPath`
  - save graph to `flowScriptPath`
- Batch compile:
  - `StateMachineGraph` toolbar exposes `Compile All`
  - invokes `StatemachineFlowScript::compileAll(...)` across transitions

### Runtime condition chunk shape

Saved transition Lua chunks are runtime-callable factories:

```lua
return function(t)
    ...
end
```

Default new-link/fallback condition:

```lua
return function(t)
    return false
end
```

## Runtime evaluation path

Runtime files:
- `Glitter/Headers/Controls/statemachine.hpp`
- `Glitter/Sources/statemachine.cpp`
- `Glitter/Headers/LuaEngine/LuaCondition.hpp`

Behavior:
- `StateMachine::loadContext<T>(...)` stores context pointer and callbacks.
- Lua evaluation callback builds a Lua table from reflected `T` fields and passes it as `t`.
- `LuaCondition` lazily compiles function chunks.
- `StateMachine::evaluateLuaCondition(...)` catches exceptions and returns `false` on failure.

## Notes

- There is no Lua -> graph decompile path anymore.
- `.flowscript` is the editor source of truth; `.lua` is a generated runtime artifact.
